# Silence Microsoft telemetry in three layers

You can cut Microsoft's phone-home traffic to a trickle, but Pi-hole can't do it alone. Until this week your Pi-hole wasn't applying your own list at all. **Pi-hole v6 throws away any Adblock line that isn't exactly `||domain^`, so it rejected all 56 `$important` rules in `list.txt`.** That is now fixed. A working setup has three layers. The first is DNS. Subscribe to the new `microsoft.txt` (218 rules) and to HaGeZi's `native.winoffice`, the maintained replacement for WindowsSpyBlocker, whose data hasn't changed since May 2022. Add `microsoft-allowlist.txt` as a Pi-hole *Allowlist* so no broad list can break Windows Update, sign-in or Defender. Add `microsoft-aggressive.txt` only if you can live without the features it names. The second layer is enforcement. Redirect port 53 at the router, block port 853 and known DNS-over-HTTPS (DoH) resolvers, and turn DoH off in Windows and Edge. Any device that can reach another resolver skips Pi-hole. The third layer is the operating system. **Only Enterprise, Education and IoT/LTSC editions honor "diagnostic data off".** Home and Pro can go no lower than "Required", so on those you disable the DiagTrack service and its scheduled tasks and re-apply after every feature update. Office, Edge and the dev tools each have their own switches. Phones follow the same pattern, but worse. Android's largest telemetry flows and the iPad's App Store analytics use hostnames that also carry Play Store downloads and iOS updates. DNS blocking removes the ads and third-party analytics, but Google's and Apple's own core telemetry keeps flowing. Routers are the easy part: turn off vendor analytics and the URL-checking "security" add-ons, and point the router's own DNS at Pi-hole.

## Pi-hole was discarding every rule, and it ignores `@@` in blocklists

The most important finding comes from Pi-hole's own source, not from Microsoft. Pi-hole v6 imports Adblock Plus–style lists through the `valid_abp_domain` check in the FTL gravity parser. **That check accepts only lines shaped exactly `||domain^`, with `^` as the last character.** Such a line blocks the domain and every subdomain. Any line with a modifier, such as `||doubleclick.net^$important`, fails as invalid, and cosmetic `##` rules are skipped ([Pi-hole FTL gravity-parseList.c](https://github.com/pi-hole/FTL/blob/master/src/tools/gravity-parseList.c)). Your original `list.txt` put `$important` on all 56 rules, so **Pi-hole imported zero of them**. The `$important` suffixes were stripped on branch `claude/microsoft-telemetry-blocklists-kqx75k`, and every new list file was checked against a port of Pi-hole's parser (`scripts/check_pihole.py`). Keep running that script before you push. A single stray modifier silently removes a rule from Pi-hole while uBlock Origin keeps applying it, so the list looks fine in a browser.

The parser has a second consequence that changes which lists you can use. **An `@@||domain^` exception line inside a list added as a Pi-hole *blocklist* is not honored.** It fails validation too. Allow rules only work in a list added as an *Allowlist* ([Pi-hole FTL gravity-parseList.c](https://github.com/pi-hole/FTL/blob/master/src/tools/gravity-parseList.c)). Lists that block whole Microsoft domains and then carve out exceptions therefore behave very differently in Pi-hole than in a browser. privacyfilters' "Microsoft-Blocker" blocks the root domains `microsoft.com`, `live.com`, `office.com`, `windows.com` and `windowsupdate.com`, then re-allows Update, Defender, NCSI (the "No internet" check) and certificate revocation with 27 `@@` rules ([Microsoft-Blocker](https://codeberg.org/privacyfilters/Microsoft-Blocker)). In Pi-hole those exceptions disappear, **so that list blocks Windows Update, the connectivity check and certificate revocation outright.** The same parser rule explains the repo's layout. Blocking lives in `microsoft.txt`, `microsoft-aggressive.txt`, `apple.txt` and `android.txt`. The 34 "must keep working" hosts live in a separate `microsoft-allowlist.txt` that you add through Pi-hole's "Add allowlist" button ([repo README](https://github.com/leptest/adblock-list/blob/claude/microsoft-telemetry-blocklists-kqx75k/README.md)). Pi-hole's allowlist wins over every blocklist, so that file also stops *other* aggressive lists you subscribe to later from breaking Windows.

Two practical notes follow. First, the raw URLs of the form `https://raw.githubusercontent.com/leptest/adblock-list/master/<file>` only work once the branch is merged to `master`. Second, now that Pi-hole actually applies `list.txt`, two of its existing entries have real effects: `youtubei.googleapis.com` and `redirector.googlevideo.com`. The first is the YouTube app's main API, not only its logging channel ([Leith 2021](https://www.scss.tcd.ie/doug.leith/apple_google.pdf)), and blocking the second stops video delivery. They broke the YouTube app and video playback in practice, so both have since been removed from `list.txt`; `ads.youtube.com` stays.

## Five hostname zones carry most Microsoft telemetry

Microsoft's own endpoint documentation shows that most Windows telemetry passes through a few zones. That is why a 218-rule list can cover so much. **The zone `events.data.microsoft.com` is the centre of it.** The Connected User Experiences and Telemetry service (DiagTrack) uploads to `v10`, `v10c` and `self.events.data.microsoft.com`. Windows Error Reporting and Online Crash Analysis use `umwatsonc` and `kmwatsonc` under the same zone, plus six `*watcab0[12].blob.core.windows.net` crash-upload buckets ([Microsoft Learn, Configure Windows diagnostic data](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)). `microsoft.txt` blocks the whole zone with one rule. That rule also covers `mobile.events` (VS Code), `teams.events` and Office's use of `self.events`. It then adds the legacy `vortex`, `watson` and `telemetry.microsoft.com` families and the `trafficmanager.net` CNAME targets those names resolve through, which Pi-hole's CNAME inspection catches ([Pi-hole FTL config](https://docs.pi-hole.net/ftldns/configfile/)).

The other four zones map to products. **Ads inside Windows**: Spotlight, Start "suggested apps" and tips come from `arc.msn.com`, `ris.api.iris.microsoft.com` and `fd.api.iris.microsoft.com` ([Microsoft Learn, Windows 11 endpoints](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)). **Office telemetry**: `*.pipe.aria.microsoft.com`, `nexus(rules).officeapps.live.com`, a large family of regional `*-telemetry.officeapps.live.com` hosts, and `diagnostics.office.com` / `measure.office.*` ([HaGeZi native.winoffice](https://raw.githubusercontent.com/hagezi/dns-blocklists/main/adblock/native.winoffice.txt)). **Web ads and analytics**: Bing's UET tag loads from `bat.bing.com` and `bat.bing.net` ([Microsoft Advertising CSP docs](https://github.com/MicrosoftDocs/Advertising/blob/main/advertising/msa-help/hlp_BA_CONC_UETv2CSP.md)), and Microsoft Clarity session recording uses `*.clarity.ms` plus `c.bing.com` ([Microsoft Learn, Clarity CSP](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-csp)). Keep blocking `adnxs.com` too. Microsoft shut down the Xandr Invest DSP on 28 February 2026, but its sell-side platform still serves through AppNexus hosts ([AdExchanger](https://www.adexchanger.com/online-advertising/microsoft-invest-formerly-xandr-dsp-and-formerly-appnexus-before-that-will-just-be-formerly/)). **Dev tools**: GitHub Copilot's client telemetry goes to `copilot-telemetry.githubusercontent.com` and its analytics to `collector.github.com` ([GitHub Docs](https://docs.github.com/en/copilot/reference/copilot-allowlist-reference)). VS Code once contacted `mobile.events.data.microsoft.com` even with telemetry set to off, a bug Microsoft confirmed and fixed ([microsoft/vscode#157228](https://github.com/microsoft/vscode/issues/157228)). Xbox beacons (`c.xbox.com`, `beacons.xboxlive.com`) round out the base list.

Edge is the exception. Its phone-home runs almost entirely through multi-purpose hosts. `edge.microsoft.com` alone carries sync, Password Monitor, extension-malware checks and component updates, and `www.bing.com` serves address-bar suggestions ([Microsoft Learn, Edge endpoints](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-security-endpoints)). DNS can safely remove only Edge's promotions (`api.edgeoffer.microsoft.com`) and its experiments service (`config.edge.skype.com`, in the aggressive list). The rest has to be handled with Edge policies. Microsoft also warns that blocking `edgeservices.bing.com` (Copilot in Edge) "isn't recommended… may lead to unexpected errors" ([same](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-security-endpoints)). The aggressive list blocks it anyway, because that is the whole point of removing Copilot.

The other side of the table is the set that must keep resolving. Microsoft is explicit about each of these. Blocking `login.live.com` means "the device isn't authenticated". `settings-win.data.microsoft.com` only configures data collection: "Don't block access to this endpoint. This endpoint doesn't upload Windows diagnostic data" ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)). Blocking `ctldl.windowsupdate.com` stops root certificate updates, and `www.msftconnecttest.com` drives the tray's "No internet" warning. `licensing.mp.microsoft.com` handles activation, `wdcp.microsoft.com` is Defender cloud protection, and `*.wns.windows.com` is push ([Microsoft Learn, Windows 11 endpoints](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)). All of these are in `microsoft-allowlist.txt`. One judgment call is built in. The allowlist keeps SmartScreen resolving, while BadBlock blocks it as "extremely invasive". SmartScreen does send URL and file reputation lookups to Microsoft, but it is also a malware defence. The allowlist chooses security, and you'd need to drop those lines to follow BadBlock.

## DNS blocking leaks through DoH, hosts-file bypass and pinned TLS

A blocklist only affects queries that reach Pi-hole, and Windows has several ways around it. **Windows ignores the hosts file for a built-in list of Microsoft domains** stored in `dnsapi.dll`, including `update.microsoft.com` and `go.microsoft.com`, a behaviour dating back to XP SP2 ([Petri](https://petri.com/windows-10-ignoring-hosts-file-specific-name-resolution/)). Since July 2020, **Defender flags a hosts file that redirects Microsoft telemetry domains as `SettingsModifier:Win32/HostsFileHijack` (severity "Severe")** ([BleepingComputer](https://www.bleepingcomputer.com/news/microsoft/windows-10-hosts-file-blocking-telemetry-is-now-flagged-as-a-risk/)), and its fix resets the whole hosts file. That's why network DNS is the right layer and hosts-file tools such as Spybot Anti-Beacon are not. Two things can't be blocked at all. Microsoft says "CRL and OCSP network traffic cannot be disabled", and it expects outbound traffic during updates and after "Reset this PC" ([Microsoft Learn, Manage connections](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services)). And because "all diagnostic data is encrypted using TLS and uses certificate pinning", you can't open the payloads to check them. You can only see *where* traffic goes ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)).

Encrypted DNS is the bigger leak because it's silent. Windows upgrades to DoH automatically only when the configured server is on its built-in list, which covers Cloudflare, Google and Quad9. A Pi-hole address is therefore safe unless someone adds a public resolver as a secondary. The Group Policy setting "Configure DNS over HTTPS (DoH) name resolution" = **Prohibit** closes that door for Windows itself ([Microsoft Learn, DoH client](https://learn.microsoft.com/en-us/windows-server/networking/dns/doh-client-support)). Browsers need their own settings. Set Edge's `DnsOverHttpsMode` to `off` ([Edge policy reference](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies)); Chrome has a policy with the same name. Pi-hole already answers Firefox's `use-application-dns.net` canary by default ([Pi-hole FTL config](https://docs.pi-hole.net/ftldns/configfile/)). None of that stops an app or IoT device with a hard-coded resolver. Pi-hole's own community says you "still need to block communications to any resolver from anything other than your intended internal DNS" ([Pi-hole Discourse](https://discourse.pi-hole.net/t/blocking-dns-over-https-doh/69404)). DoT can be blocked by port (TCP 853). DoH runs on 443 and can only be blocked by destination ([Pi-hole Discourse](https://discourse.pi-hole.net/t/doh-dot-bypass-pi-hole/80956)), which is what **HaGeZi's Encrypted DNS Bypass list** (`doh.txt`, 3,334 entries) is for ([HaGeZi doh.txt](https://raw.githubusercontent.com/hagezi/dns-blocklists/main/adblock/doh.txt)). Encrypted-DNS bypass is not hypothetical: XDA observed smart-home gadgets reaching telemetry servers that Pi-hole had blocked ([XDA](https://www.xda-developers.com/smart-home-gadgets-ignoring-pi-hole-encrypted-dns/)).

The enforcement layer therefore lives on the router. NAT-redirect every outbound UDP/TCP 53 packet not sent by Pi-hole to Pi-hole. Drop outbound 853. Load the DoH list into Pi-hole. Don't hand out any public resolver as a secondary DNS server, because clients will use it. Then verify. After a reboot and an idle period, Pi-hole's query log should show blocked `*.events.data.microsoft.com` and `watson` lookups from each Windows PC. If a machine shows none of Microsoft's usual chatter, it is probably resolving somewhere else.

## Only Enterprise and Education editions can switch telemetry off

Windows' own diagnostic-data setting has an edition floor that no blocklist can fix. The policy `AllowTelemetry` (`HKLM\Software\Policies\Microsoft\Windows\DataCollection`) takes 0 = off, 1 = Required, 3 = Optional. **"Diagnostic data off" is "only available on Windows Server, Windows Enterprise, and Windows Education editions"**, and Required is the default ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)). Required is not trivial. It includes device, network and processor attributes, installed-app lists and driver data, and on devices with a cellular modem it includes the IMEI. Microsoft also notes that these settings govern Windows components only. Microsoft 365 Apps and other Microsoft apps "may also collect and send diagnostic data using their own controls" ([same](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)). So on Home and Pro, the practical floor is AllowTelemetry=1, plus disabling the DiagTrack service and the Compatibility Appraiser task under `\Microsoft\Windows\Application Experience`. That task runs CompatTelRunner independently of the service ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/3987504/how-to-completely-and-permanently-disable-delete-w)). Users consistently report that **feature updates restore services and tasks to their defaults** ([MakeUseOf](https://www.makeuseof.com/this-windows-process-comes-back-after-every-update-and-quietly-chews-through-your-files/)), so re-apply after each one. Policy-registry values survive updates better than service start types. The only supported way to turn telemetry fully off is Enterprise, Education or IoT Enterprise LTSC. LTSC 2024 gets 10 years of security-only updates and a frozen feature set ([Microsoft Learn, LTSC 2024](https://learn.microsoft.com/en-us/windows/iot/iot-enterprise/whats-new/windows-11-iot-enterprise-ltsc-2024)).

The policies that matter beyond diagnostic data are documented in one place ([Microsoft Learn, Manage connections](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services)). Home has no Group Policy editor, so there you set the same values as registry entries or through a reviewed tool.

| Control | Policy value (DWORD) | Editions |
|---|---|---|
| Diagnostic data | `DataCollection\AllowTelemetry` = 0 (Ent/Edu) or 1 (Home/Pro) | All; 0 honored only on Ent/Edu/Server |
| Consumer "experiences" (auto-installed apps, promos) | `CloudContent\DisableWindowsConsumerFeatures=1` | All via registry |
| Spotlight | `CloudContent\DisableWindowsSpotlightFeatures=1` | All via registry |
| Tailored experiences | `HKCU\...\CloudContent\DisableTailoredExperiencesWithDiagnosticData=1` | All |
| Advertising ID | `AdvertisingInfo\DisabledByGroupPolicy=1` | All |
| Activity history | `System\EnableActivityFeed=0`, `PublishUserActivities=0`, `UploadUserActivities=0` | All |
| Web results in Search | `Windows Search\DisableWebSearch=1`, `ConnectedSearchUseWeb=0`, `AllowCortana=0` | All |
| Error reporting | `Windows Error Reporting\Disabled=1` | All |
| CEIP | `SQMClient\Windows\CEIPEnabled=0` | All |
| OneDrive | `OneDrive\DisableFileSyncNGSC=1` | All |
| DoH | "Configure DNS over HTTPS" = Prohibit | All |

AI features are moving targets. **`AllowRecallEnablement=0` removes Recall and deletes its snapshots on Pro, Enterprise and Education** (24H2 build 26100.3915+). `TurnOffWindowsCopilot` is officially deprecated and "isn't for the new Copilot experience" ([Microsoft Learn, WindowsAI CSP](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-windowsai)). In practice that means uninstalling the Copilot app, plus the aggressive list's DNS blocks. Office has its own switches under `HKCU\Software\Policies\Microsoft\office\16.0\common\privacy` and `...\office\common\clienttelemetry\sendtelemetry` (3 = Neither). Even at "Neither", "required service data will be sent" ([Microsoft Learn, M365 privacy controls](https://learn.microsoft.com/en-us/microsoft-365-apps/privacy/manage-privacy-controls)). The dev tools use environment variables and settings: `DOTNET_CLI_TELEMETRY_OPTOUT=1` ([.NET docs](https://learn.microsoft.com/en-us/dotnet/core/tools/telemetry)), `POWERSHELL_TELEMETRY_OPTOUT=1` ([PowerShell docs](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_telemetry)), and `"telemetry.telemetryLevel": "off"` in VS Code ([VS Code docs](https://code.visualstudio.com/docs/configure/telemetry)).

Accounts matter as much as settings. **From 24H2, signing in with a Microsoft account during setup turns on device encryption and backs the BitLocker recovery key up to that account, on every edition including Home** ([ElcomSoft](https://blog.elcomsoft.com/2025/05/forensic-implications-of-bitlocker-by-default-in-windows-11-24h2/)). A local account avoids the escrow. Microsoft is removing the setup workarounds for creating one, according to Insider reports ([WindowsForum](https://windowsforum.com/threads/windows-11-oobe-now-account-first-local-account-bypass-removed-in-insider.383368/)). If you want a tool to handle the registry work, the defensible choices are O&O ShutUp10++ (it now covers Copilot and Recall) and the open-source, revertible privacy.sexy ([O&O blog](https://blog.oo-software.com/en/new-oo-shutup10-2-0-1009-now-with-copilot-removal-app-uninstall-recall-data-deletion/); [privacy.sexy](https://github.com/undergroundwires/privacy.sexy)). privacy.sexy itself says to re-run after major OS updates. Avoid anything that disables Windows Update, root-certificate updates, Defender or the Microsoft Account Sign-In Assistant. Microsoft warns that losing the last one means Windows 10 1709+ and Windows 11 stop offering feature updates ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services)).

## Phones leak through the same hostnames that keep them working

### Android: Google's telemetry shares hosts with the Play Store

Trinity College Dublin's measurements set the baseline. **An idle Pixel contacted Google about every 4.5 minutes. It sent about 1 MB in its first 10 minutes and about 1 MB every 12 hours while idle, with "Usage & diagnostics" turned off.** The iPhone in the same test sent 42 KB and 52 KB ([Leith 2021](https://www.scss.tcd.ie/doug.leith/apple_google.pdf)). The bulk of it goes to hosts Pi-hole can't touch. Clearcut telemetry goes to `play.googleapis.com/log/batch`, 1.1 MB of device data to `www.googleapis.com/experimentsandconfigs`, and a check-in to `android.clients.google.com` that links IMEI, serial number and Wi-Fi MAC to the persistent Android ID. Pi-hole users who blocked `play.googleapis.com` found Play downloads stuck on "Pending" ([pi-hole #2503](https://github.com/pi-hole/pi-hole/issues/2503)). A 2025 follow-up found that Play Services contacts `googleads.g.doubleclick.net` right after sign-in and stores a DSID advertising cookie "without consent… and there is no opt out" ([Leith 2025](https://www.scss.tcd.ie/doug.leith/pubs/cookies_identifiers_and_other_data.pdf); [The Register](https://www.theregister.com/security/2025/03/04/googles-consent-less-android-tracking-probed-by-academics/1220113)). Your `||doubleclick.net^` rule, now actually applied, blocks that contact.

What DNS *can* remove is the ad and analytics layer, plus OEM telemetry. `android.txt` (138 rules) blocks `app-measurement.com`, `google-analytics.com`, `googleadservices.com`, Firebase and Crashlytics logging, `federatedml-pa.googleapis.com` and SwiftKey telemetry. It adds per-brand telemetry and ad hosts for Samsung, Xiaomi, OPPO/Realme/OnePlus, Huawei/Honor and Vivo. It deliberately leaves out push (`mtalk.google.com`, `fcm.googleapis.com`, Mi Push `xmpush`, HeyTap push, Vivo `vpush`), sign-in and connectivity checks, all of which Google or the vendors list as required ([Google, Android Enterprise network requirements](https://support.google.com/work/android/answer/10513641?hl=en)). One entry to watch is `google-analytics.com`. Google lists it under "Google Play and updates". No breakage has been reported, but it's the first thing to allow if Play updates misbehave. OEM telemetry is worth the effort. On EU handsets, **Samsung, Xiaomi, Huawei and Realme sent substantial data to the vendor and to third parties "even when minimally configured", with no opt-out**. The volume sent to Google was 10–30× the volume sent to the OEM ([Leith OEM study](https://www.scss.tcd.ie/doug.leith/Android_privacy_report.pdf)). For phones you own, add the matching maintained HaGeZi list (`native.samsung`, `native.xiaomi`, `native.oppo-realme`, `native.huawei`, `native.vivo`). But **HaGeZi's Xiaomi list includes Mi Push hosts**, which can break notifications for apps that use Mi Push ([HaGeZi native.xiaomi](https://raw.githubusercontent.com/hagezi/dns-blocklists/main/adblock/native.xiaomi.txt)).

On the phone itself, keep **Private DNS on Off or Automatic**. Automatic tries DoT and falls back to Pi-hole, because Pi-hole doesn't answer on 853. A named provider in strict mode bypasses Pi-hole completely ([Android Developers Blog](https://android-developers.googleblog.com/2018/04/dns-over-tls-support-in-android-p.html); [Pi-hole Discourse](https://discourse.pi-hole.net/t/no-internet-with-pi-hole-when-using-androids-private-dns-feature/71818)). Delete the advertising ID. Apps then read zeros ([Play Console Help](https://support.google.com/googleplay/android-developer/answer/6048248?hl=en)). Turn off Usage & diagnostics and the OEM toggles, including Samsung's Customization Service, and re-check them after One UI updates ([MakeUseOf](https://www.makeuseof.com/turn-off-samsung-customization-service-for-privacy/)). These settings shrink the collection but don't stop it; Leith's testers turned them all off and data kept flowing. ADB debloating with UAD-ng removes OEM agents without root ([UAD-ng](https://github.com/Universal-Debloater-Alliance/universal-android-debloater-next-generation/)). In the 2021 study, only LineageOS without Google apps and /e/OS sent nothing to their developers, and /e/OS sent nothing to Google either.

### iPad: xp.apple.com is the analytics host you can't safely block

Apple sends far less than Google, but the "Share Analytics" switch doesn't mean what it says. Leith found iOS sending telemetry to `xp.apple.com` even after "Don't Share" was chosen at setup ([Leith 2021](https://www.scss.tcd.ie/doug.leith/apple_google.pdf)). Researchers Mysk showed that the App Store, Music, TV, Books and Stocks send detailed usage analytics to that same host with analytics off, tagged with the account-linked DSID ([Gizmodo](https://gizmodo.com/apple-iphone-privacy-dsid-analytics-personal-data-test-1849807619)). The resulting class action was dismissed with leave to amend in January 2026 ([9to5Mac](https://9to5mac.com/2026/01/21/california-court-rules-that-apple-didnt-invade-the-privacy-of-iphone-users/)). **Apple also documents `xp.apple.com` as "Software update support"** ([Apple 101555](https://support.apple.com/en-us/101555)), and users report that blocking it broke HomePod updates ([HaGeZi #930](https://github.com/hagezi/dns-blocklists/issues/930)). That's why `apple.txt` (22 rules) leaves it alone. It blocks the hosts that both HaGeZi Light/Normal and the AdGuard DNS filter already ship to millions of users without complaint: `metrics`, `securemetrics`, `supportmetrics`, `metrics.icloud.com`, the `*-analytics-events` family for News, Stocks, Books, Notes, Weather, Podcasts and TV, and Search Ads attribution (`iadsdk`, `api-adservices`) ([AdGuard DNS filter](https://adguardteam.github.io/AdGuardSDNSFilter/Filters/filter.txt)). If you want the maximum, HaGeZi `native.apple` (109 entries) *does* block `xp.apple.com`. Then you need to allowlist it temporarily whenever you update the iPad.

Pi-hole handles the iPad's main bypass by default. Apple asks networks that want to opt out of iCloud Private Relay to return NXDOMAIN for `mask.icloud.com` and `mask-h2.icloud.com`. The device then alerts the user instead of silently routing around the network ([Apple Developer](https://developer.apple.com/support/prepare-your-network-for-icloud-private-relay/)). Pi-hole v6 does this out of the box (`dns.specialDomains.iCloudPrivateRelay`). It also returns NODATA for `resolver.arpa`, which stops Discovery of Designated Resolvers (DDR) from upgrading devices to encrypted DNS behind Pi-hole's back ([Pi-hole FTL config](https://docs.pi-hole.net/ftldns/configfile/)). What remains is on the device. Don't install encrypted-DNS configuration profiles or VPN apps unless they point at Pi-hole ([Apple DNSSettings](https://developer.apple.com/documentation/devicemanagement/dnssettings)). Turn off all Analytics & Improvements toggles, Personalized Ads, "Allow Apps to Request to Track" ([Apple 102420](https://support.apple.com/en-us/102420)) and the location System Services. Also turn off Photos' **Enhanced Visual Search, which has been on by default since iOS 18.1** ([The Register](https://www.theregister.com/2025/01/03/apple_enhanced_visual_search/)). For Siri, turn off "Learn from this app" and Siri's location access. Lumia showed Siri sending installed-app lists, location and dictated message content to `*.smoot.apple.com` and `guzzoni.apple.com` ([Lumia AppleStorm](https://www.lumia.security/blog/applestorm)). Don't block those two domains broadly, because they also run Spotlight, Safari suggestions and Siri. The App Privacy Report (Settings > Privacy & Security) lists the domains each app actually contacts, which makes it the best source of new hostnames for `apple.txt`.

## Routers phone home mostly through optional cloud and security features

Router telemetry is modest next to the "security" add-ons some vendors bundle. **ASUS AiProtection sends Trend Micro the "URLs, Domains and IP addresses of websites visited"** ([MBReviews](https://www.mbreviews.com/trend-micro-aiprotection-asus/)). Netgear Armor checks outgoing HTTP/HTTPS requests against Bitdefender's cloud ([NETGEAR Community](https://community.netgear.com/discussions/en-home-armor/armor-and-privacy/2202948)). Turning those off (ASUS: Administration > Privacy > Withdraw; Netgear: Settings > Security in the app) does more for privacy than any blocklist, though it costs ASUS owners AiProtection, Adaptive QoS and the traffic analyzers. Netgear's device analytics can be disabled under Advanced > Administration > Router Update ([Pi-hole Discourse](https://discourse.pi-hole.net/t/netgear-now-collects-router-analytics-data-here-are-the-steps-to-disable-it/3306)). US owners of newer models may have to opt out by email ([NETGEAR KB](https://kb.netgear.com/000064225/I-live-in-the-European-Union-or-United-Kingdom-how-do-I-opt-out-of-NETGEAR-analytics-data-collection)). The hostnames people have actually captured from routers are few. Netgear uses `registration`, `presence` and `advisor.ngxcld.com` ([anthony-wang netgear.txt](https://github.com/anthony-wang/PiHoleBlocklist/blob/master/netgear.txt)). UniFi's analytics goes to `trace.svc.ui.com` ([UniHosted](https://www.unihosted.com/blog/unifi-s-internet-history-checking-information-on-privacy-and-data-handling-by-unifi)). TP-Link's cloud runs on `tplinkcloud.com` and `tplinknbu.com`, and blocking them only costs remote and app access ([sappafrancesco TP-Link](https://github.com/sappafrancesco/dns-blocklists/blob/main/vendors/tplink/README.md)). Keep firmware-update and connectivity-check hosts reachable. When those checks fail, routers tend to retry constantly, which is the likely cause of the heavy `updates1.netgear.com` and `www.tp-link.com` query volumes Pi-hole users report ([pi-hole #2982](https://github.com/pi-hole/pi-hole/issues/2982)). eero has no opt-out short of unplugging it ([How-To Geek](https://www.howtogeek.com/eeros-silent-cloud-syncs-are-turning-your-router-into-yet-another-tracking-device/)). An ISP gateway's TR-069 management channel runs from its WAN side, so no LAN DNS can reach it. Bridge mode behind your own router limits what it can see ([Computerworld](https://www.computerworld.com/article/1525268/home-routers-supplied-by-isps-can-be-compromised-en-masse.html)). The caveat that matters for you: **Pi-hole only sees the router's own lookups if the router's WAN DNS points at Pi-hole** ([TP-Link FAQ](https://www.tp-link.com/us/support/faq/3230/)). A router that uses DoT upstream (ASUS supports this) bypasses Pi-hole for everything it resolves itself.

## Conclusion

The weakest point in this setup was the list format, not the choice of lists. A filter list that works in uBlock Origin can fail silently in Pi-hole, and a list built on `@@` exceptions can block exactly what it meant to protect. Treat Pi-hole compatibility as something you test (`check_pihole.py`), not something you assume. The same pattern runs through every platform. Microsoft, Google and Apple each run their most valuable telemetry through hostnames that also carry something you need: `events.data.microsoft.com` for Xbox and M365, `play.googleapis.com` for app downloads, `xp.apple.com` for updates. So "as completely as possible" is really a series of trades, and each blocklist marks where the trade becomes too costly. On Windows you can push much further than on phones, because Microsoft documents its endpoints and exposes real policy switches. The ceiling is the edition you run. Home and Pro will always send Required diagnostic data unless you're willing to fight DiagTrack after every update. Enterprise, Education or LTSC is the only supported way to turn it off.

Two things will need upkeep. The repo lists are hand-maintained snapshots and Microsoft renames hosts, so pairing them with HaGeZi's feeds, which rebuild every few hours, is what keeps coverage from decaying the way WindowsSpyBlocker's did. And much of the research is dated: the newest peer-reviewed phone measurements are Android 14 and iOS 13-era, and Microsoft publishes no per-build (24H2 vs 25H2) endpoint diff for Windows. Your own Pi-hole query log and the iPad's App Privacy Report are now better sources of new hostnames than published lists, and they should drive future additions.
