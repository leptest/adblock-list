## 1. Windows 10/11 diagnostic data (DiagTrack / Connected User Experiences and Telemetry), Windows Error Reporting, Online Crash Analysis

### Takeaway
Microsoft's own docs name a small core set of Windows telemetry uploaders: `v10.events.data.microsoft.com`, `v10c.events.data.microsoft.com`, `v10.vortex-win.data.microsoft.com`, `self.events.data.microsoft.com` (DiagTrack), the `watson`/`umwatsonc`/`kmwatsonc` WER and OCA hosts plus six `*watcab0[12].blob.core.windows.net` crash-upload blobs. All of these are safe to block on consumer machines. It only breaks crash reporting and diagnostics, and for Entra/Intune-managed fleets it also breaks Windows Update for Business reports, Autopatch and the "diagnostic data processor" configuration. `settings-win.data.microsoft.com` gets flagged "don't block" by Microsoft because it's config, not upload.

### Cited Findings
**Core DiagTrack/UTC uploaders (Microsoft-documented), safe to block for home users; breaks enterprise diagnostic-data-dependent services:**
- `v10.events.data.microsoft.com`, `v10c.events.data.microsoft.com` and `v10.vortex-win.data.microsoft.com` are the "Connected User Experiences and Telemetry" endpoints. — [MS-DIAG](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)
- `self.events.data.microsoft.com` and `v10.events.data.microsoft.com` are "used by the Connected User Experiences and Telemetry component and connects to the Microsoft Data Management service. If you turn off traffic... diagnostic and usage information... isn't sent back to Microsoft." — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- Win11 Enterprise's "Diagnostic Data" group also lists `functional.events.data.microsoft.com`, `browser.events.data.msn.com` and `www.microsoft.com`. Don't block `www.microsoft.com`, since it's the main website. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- Enterprise "Windows diagnostic data processor configuration" (Entra-joined devices) needs `us-v10c.events.data.microsoft.com` / `eu-v10c.events.data.microsoft.com` (EU Data Boundary), `watsonc.events.data.microsoft.com` / `eu-watsonc.events.data.microsoft.com`, `settings-win.data.microsoft.com` and `*.blob.core.windows.net` to be reachable. — [MS-DIAG](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization)

### Inferences
- Wildcarding `events.data.microsoft.com` (as HZ does) covers v10/v10c/v20/self/umwatsonc/kmwatsonc/watsonc/functional/mobile/teams subdomains in one rule. The catch is that the same zone serves Office, Teams, VS Code and Edge diagnostics too (see sections 3, 6 and 7), and M365 lists `*.events.data.microsoft.com` as "Required" for enterprise tenants.
- `vortex*`, `sqm.*`, `*.df.telemetry.microsoft.com` and `watson.microsoft.com` are legacy (Windows 7/8/early-10 era). MS-W11E, the current Windows 11 doc, no longer lists them, but blocking them costs nothing.
- For an ABP/Pi-hole list, `||watson.*.microsoft.com^` can't be a hosts entry. Enumerate the concrete hosts instead (watson.telemetry, watson.events.data, watsonc.events.data, etc.).

### Gaps
- Microsoft's current Win11 doc was captured against "the latest version of Windows 11" without naming 24H2 vs 25H2. I found no Microsoft per-build (24H2/25H2) endpoint diff.
- The Windows 10 22H2 Enterprise endpoint page URL I tried (`manage-windows-22h2-endpoints`) returned an error/empty page, so I didn't verify Windows 10-specific differences directly.
- I found no primary source confirming the exact role of `v20.events.data.microsoft.com` beyond its presence in WSB-extra.

## 2. Windows ads and "experiences": Spotlight, Start/tips, Widgets/News, Bing in Start/Search, Copilot/Recall, Activity History, location, advertising ID

### Takeaway
Spotlight, tips and Start "suggested apps" come from `arc.msn.com`, `ris.api.iris.microsoft.com` and `fd.api.iris.microsoft.com` plus MSN content hosts, and Widgets pull from `*.msn.com`, `widgetservice.azurefd.net` and `widgetcdn.azureedge.net`. Blocking these is safe but kills Spotlight images, Widgets and the Weather/news feeds. Bing search hosts (`www.bing.com`, `business.bing.com`, `th.bing.com`, `r.bing.com`) are shared with normal web search and Edge, so block them only if you accept that web search breaks. Recall is documented as local-only. I found no authoritative endpoint list for Windows Copilot.

### Cited Findings
**Windows Spotlight / tips / suggested apps, safe to block; breaks Spotlight lock-screen images, suggested apps, Microsoft account notifications and Windows tips:**
- `arc.msn.com`, `ris.api.iris.microsoft.com`, `api.msn.com`, `assets.msn.com`, `c.msn.com`, `ntp.msn.com`, `srtb.msn.com`, `www.msn.com`, `fd.api.iris.microsoft.com` and `staticview.msn.com` are used "to retrieve Windows Spotlight metadata... as well as suggested apps, Microsoft account notifications, and Windows tips". — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- GPO route: "Turn off all Windows spotlight features" / `DisableWindowsSpotlightFeatures`=1. "Turn off Microsoft consumer experiences" is `DisableWindowsConsumerFeatures`=1. — [MS-CONN](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services)
- HZ blocks `arc.msn.com`, `arc-emea.msn.com`, `arc1.msn.com`, `arc2.msn.com`, `arc3.msn.com`, `arc5.msn.com`, `arc9.msn.com` and `srtb.msn.com`. It does not block `ris.api.iris.microsoft.com`, `api.msn.com` or `assets.msn.com`. — [HZ](https://github.com/hagezi/dns-blocklists/blob/main/wildcard/native.winoffice-onlydomains.txt)
- WSB-extra (not "spy") holds `arc.msn.com`, `arc.msn.com.nsatc.net`, `ris.api.iris.microsoft.com`, `api.msn.com`, `assets.msn.com`, `ntp.msn.com`, `img-s-msn-com.akamaized.net` and `cdn.content.prod.cms.msn.com`. — [WSB-extra](https://github.com/crazy-max/WindowsSpyBlocker/blob/master/data/hosts/extra.txt)
- Win11 Enterprise (Store area): `img-s-msn-com.akamaized.net` and `img-prod-cms-rt-microsoft-com.akamaized.net` are used "to download image files that are called when applications run (Microsoft Store or Inbox MSN Apps)". ### Inferences
- Blocking `arc.msn.com` + `ris.api.iris.microsoft.com` + `fd.api.iris.microsoft.com` is the minimal "no Spotlight/Start suggestions" set. Adding `*.msn.com` breaks MSN websites, Weather and the Widgets board.
- `c.bing.com` is dual-use. Microsoft lists it for Windows Cortana/Live Tiles *and* as a Microsoft Clarity collection host (section 5), so blocking it is ad/analytics-positive, and Windows impact is limited to tiles/tips.
- `www.bing.com` should be "do not block" for a general-purpose list, because it is Bing search itself and Edge's address-bar autosuggest (`https://www.bing.com/qbox`, per MS-EDGE).

### Gaps
- I found no authoritative hostname list for Windows Copilot (the app/taskbar). A low-quality aggregator (alibaba.com "product-insights") claimed traffic to `api.copilot.microsoft.com` and `ai.api.microsoft.com`, but it isn't a credible source and I excluded it.
- I found no primary source for `g.live.com` as ad/Spotlight. Microsoft lists it only under OneDrive (section 6).
- No public source enumerates the 24H2/25H2 "Start menu Recommended / account notifications" ad hosts separately from the Spotlight/iris set above.

## 3. Office / Microsoft 365 Apps telemetry and Connected Experiences

### Takeaway
Office telemetry is spread across `*.events.data.microsoft.com` (esp. `self.events.data.microsoft.com`), `*.pipe.aria.microsoft.com`, `nexus.officeapps.live.com`/`nexusrules.officeapps.live.com` and a large family of `*-telemetry.officeapps.live.com` web-app hosts. Microsoft's own M365 endpoint service marks `*.aria.microsoft.com` and `*.events.data.microsoft.com` as **required** for M365 tenants, and `officeclient.microsoft.com` is also required (config/licensing). Block the telemetry-named hosts, but treat `officeclient.microsoft.com`, `ecs.office.com` and `config.edge.skype.com` as "breaks features".

### Cited Findings
- The M365 endpoint service (version 2026081400), endpoint ID 69, "Common / Default / required=True", lists `*.aria.microsoft.com` and `*.events.data.microsoft.com`. — [MS-M365](https://endpoints.office.com/endpoints/worldwide?clientrequestid=b10c5ed1-bad1-445f-b386-b919946339a7)

## 7. Shared / required hostnames: "do not block" or "blocks feature X"

### Takeaway
Several hostnames that people often find in telemetry lists are functionally required: auth (`login.live.com`), Windows Update/Delivery Optimization, certificate trust lists (`ctldl.windowsupdate.com`), NCSI (`www.msftconnecttest.com`), activation/licensing, Store, WNS push, settings, Defender/SmartScreen and Edge services. A consumer blocklist must exclude these (ideally with `@@` allow rules).

### Cited Findings
- **Auth:** `login.live.com` authenticates the device ("If you turn off traffic for this endpoint, the device isn't authenticated") and handles MSA sign-in. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints). MS-DIAG: "We don't recommend disabling this endpoint." — [MS-DIAG](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization). M365 requires `login.microsoftonline.com`, `login.microsoft.com`, `login.windows.net`, `graph.microsoft.com` and others (endpoint ID 56). — [MS-M365](https://endpoints.office.com/endpoints/worldwide?clientrequestid=b10c5ed1-bad1-445f-b386-b919946339a7)
- **Certificates:** `ctldl.windowsupdate.com` (Automatic Root Certificates Update. Blocking it means apps and websites "might stop working" and untrusted-cert lists aren't updated) and `ocsp.digicert.com`. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints). `crl.microsoft.com` appears in MS-CONN. — [MS-CONN](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services)
- **NCSI:** `www.msftconnecttest.com` and `ipv6.msftconnecttest.com`. Without them "the network status tray icon shows a warning". — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints). `www.msftncsi.com` also appears in MS-CONN. — [MS-CONN](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services)
- **Activation/licensing:** `licensing.mp.microsoft.com` ("blocks online activation and app licensing") — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints); `activation-v2.sls.microsoft.com` — [MS-CONN](https://learn.microsoft.com/en-us/windows/privacy/manage-connections-from-windows-operating-system-components-to-microsoft-services).
- **Windows Update / Delivery Optimization:** `*.prod.do.dsp.mp.microsoft.com` (DO metadata; blocking causes corruption/redownloads and no peer caching), `*.dl.delivery.mp.microsoft.com`, `*.windowsupdate.com`, `*.delivery.mp.microsoft.com`, `*.update.microsoft.com`, `adl.windows.com` (compat DB), `tsfe.trafficshaping.dsp.mp.microsoft.com`, `*.api.cdp.microsoft.com` and `definitionupdates.microsoft.com`. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints). WSB keeps these in a separate `update.txt` (dominated by `*.wns.windows.com`, `*.l.windowsupdate.com` and `*.prod.do.dsp.mp.microsoft.com`), meant for users who deliberately block updates. — [WSB-update](https://github.com/crazy-max/WindowsSpyBlocker/blob/master/data/hosts/update.txt)
- **Store:** `*displaycatalog.mp.microsoft.com`, `storeedgefd.dsx.mp.microsoft.com`, `livetileedge.dsx.mp.microsoft.com`, `storecatalogrevocation.storequality.microsoft.com` (malicious-app revocation) and `share.microsoft.com`. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- **Push:** `*.wns.windows.com`. Blocking it kills push notifications, MDM, mail sync and settings sync. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- **Settings/config:** `settings-win.data.microsoft.com` and `settings.data.microsoft.com`. — [MS-DIAG](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization); [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- **Other functional:** `fs.microsoft.com` (font streaming), `dmd.metaservices.microsoft.com` (device metadata), `maps.windows.com` / `ecn.dev.virtualearth.net` (offline maps), `tile-service.weather.microsoft.com` (Weather), `cdn.onenote.net`, `evoke-windowsservices-tas.msedge.net` (Photos app config) and `to-do.microsoft.com`. — [MS-W11E](https://learn.microsoft.com/en-us/windows/privacy/manage-windows-11-endpoints)
- **M365 required:** `*.aria.microsoft.com`, `*.events.data.microsoft.com` (ID 69), and `officeclient.microsoft.com` / `office15client.microsoft.com` (ID 86). — [MS-M365](https://endpoints.office.com/endpoints/worldwide?clientrequestid=b10c5ed1-bad1-445f-b386-b919946339a7)
- HZ's "native.winoffice" file includes non-Microsoft third-party telemetry that happens to sit on Azure/Microsoft-looking hostnames, such as Citrix and Qlik Event Hubs (`citrixanalyticseh.servicebus.windows.net`, `prd-qlik-telemetry.servicebus.windows.net`), `westeurope-5.in.applicationinsights.azure.com.fiege.de`, `*.nel.measure.office.net.cardano.com`, `tracker.flightview.com.trafficmanager.net`, `utm.sankei.jp.msn.com` and `collector.azure.eaglex.ic.gov` (about 25 of 388 entries). It also includes its own canary `h4g3z1-native.winoffice.web.app`. — [HZ](https://github.com/hagezi/dns-blocklists/blob/main/wildcard/native.winoffice-onlydomains.txt)
